# Single-handoff router experiment results

Paired comparison of five in-memory topologies. Production Netplane is unchanged.
Baseline for overhead ratios: `tower_bounded`.

Generated by `./scripts/bench-single-handoff.sh --quick --runs 5` (4096 samples per
run). Prefer a full matrix without `--quick` on a controlled host before merging PR 2.
Raw JSON remains under a fresh empty `target/bench-single-handoff-*` directory
(gitignored). Later tooling requires schema version 2 with explicit `repetition` IDs;
these tabulated values are unchanged from the recorded quick matrix.

## Capacity and interpretation caveats

The experimental `single_handoff` fixture preserves backend `Endpoint` bounds and a
non-blocking `max_outstanding` semaphore. It does **not** enforce GraphBuilder outer
`max_in_flight` or `buffer_capacity`. PR 2 must design an equivalent outer admission
model before replacing the production double-handoff path.

The probe `single_handoff` path also omits `Handle` admission/version selection/observation.
**Do not present the 2.2–2.8× probe speedup as the expected production improvement.**
At 32 callers: prototype 20.1 µs, production GraphDraft 40.0 µs, production GraphBuilder
50.3 µs. Criterion `single_handoff_one_route` is the topology-only comparison.

In the tables below, `*` means `all_pairs_same_direction` (every paired mean-latency
delta shared a sign). With five pairs that is sign-test p=0.0625, not significance at 0.05.

## PR 2 backpressure semantics to preserve

1. Outer `max_in_flight` concurrency bound across the routed graph version.
2. Outer `buffer_capacity` queue bound with Tower-buffer waiting/rejection behavior.
3. Global `max_outstanding`, including unpolled admitted futures.
4. Backend-local concurrency and buffer isolation.
5. Unpolled request retention, cancellation while queued, readiness ownership on the
   selected backend worker, publication/rollback, deadlines, and shutdown drain.
6. Fairness under backend imbalance (outer slots must not permanently starve an idle backend).

## Allocations and CPU

Per-request heap allocation counts were not collected: the workspace forbids `unsafe`,
which a process-wide counting allocator requires.

CPU utilization from `/proc/self/schedstat` was near zero in this run environment and
should be re-checked on a host with normal process CPU accounting before drawing
CPU-share conclusions.
